# Case-match eval harness — golden set

Offline evaluation data for `app/services/case_match.py` (the pipeline behind
`POST /client/cases`). See `backend/app/eval/` for the code, and
`backend/scripts/eval_case_match_{export,import,run}.py` for the CLI.

## Files here

- **`profiles.json`** (committed) — 14 hand-authored synthetic client personas
  (intake answers). Validated against `app/services/client_intake.py`'s
  `INTAKE_SCRIPT` chip values by `app/eval/goldens.py::load_profiles()`.
  **Never** generate this file from real `ClientProfile` rows — those are
  AES-256-GCM encrypted client PII.
- **`labels.csv`** (committed once real labels exist) — consultant-assigned
  relevance grades (0/1/2) for every (profile, case-study file) pair,
  produced by `scripts/eval_case_match_import.py` from a filled-in
  `labeling_sheet.csv`. Filename-keyed, not file_id-keyed — file UUIDs are
  regenerated on every re-upload/reseed; filenames are stable.
- **`labels.placeholder.csv`** (generated, not meant to be committed as truth)
  — `scripts/eval_case_match_export.py --bootstrap-labels` output: label=2 on
  each profile's current top-1 result, 0 elsewhere. Its metrics are perfect
  by construction and therefore meaningless — it exists only to exercise the
  harness's plumbing before any human has labeled anything.
- **`corpus_manifest.csv`** (committed, regenerated by `eval_case_match_export.py`)
  — filename → sha256 snapshot, so a later run can flag "this case's content
  changed since it was labeled" instead of silently trusting stale labels.
- **`LABELING.th.md`** (committed) — the rubric and instructions sent to a
  Brandbiz consultant alongside `labeling_sheet.csv`.
- **`out/`** (gitignored) — generated reports, run JSON, and the labeling
  sheet itself land here.

## Workflow

1. `scripts/eval_case_match_export.py` — preflight the live corpus, write
   `out/labeling_sheet.csv` + `corpus_manifest.csv` + (optionally)
   `labels.placeholder.csv`.
2. Send `out/labeling_sheet.csv` + `LABELING.th.md` to a consultant.
3. `scripts/eval_case_match_import.py` on the filled-in sheet → commit the
   resulting `labels.csv`.
4. `scripts/eval_case_match_run.py` — run retrieval in both "production
   settings" (what the client sees) and "deep pool" (what the retriever
   could reach) modes, and print/write a ranking-quality + calibration
   report. Use `--baseline <prior run-<ts>.json>` to diff against an earlier
   run when tuning `rag_top_k`, `rag_max_distance`, chunking, or the query
   builder (`--query-variant`).

See each script's module docstring for exact commands (they run inside the
`backend-api` container — `docker compose exec backend-api ...`), and
`app/eval/report.py`'s calibration verdict for how to read the AUC numbers
in a report.
